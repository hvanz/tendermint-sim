Step-by-step state machine simulator of Tendermint consensus protocol with interactive pseudocode

Features

  • Display per-node states and messages in a timeline.
  • Trigger enabled steps on nodes with a click. Undo last step.
  • Interactive pseudocode panel: enabled steps are highlighted in the code and can be fired by clicking them.
  • Before GST, model late or missing messages by clicking a sender in the inbox to mark that message as not received. Click again to restore it or acknowledge a late proposal.
  • Declare GST to reveal hidden messages, disable new delivery strikes, and give protocol actions global priority over timeouts.
  • Predefined traces: replay saved scenarios or save the current one as JSON.

Assumptions

  • 4 nodes (n = 3f+1, f = 1). Single height. Values always valid. Non-Byzantine.
  • The consensus rules follow the Tendermint paper; the GST scheduler is an educational execution model.
  • Every run starts Before GST, with unrestricted interleavings of enabled protocol and timeout actions.
  • Broadcasts enter every inbox immediately. Before GST, a per-recipient not-received mark hides a message from rule evaluation; this is an availability visualization, not a timed network model.
  • The inbox lists messages available to a node, not necessarily messages already processed. A message used by a rule cannot be retroactively marked as not received.
  • Starting a timer is modeled as a state transition. Before GST, scheduled timeout actions are freely selectable. Declare GST makes hidden messages available, disables new strikes, and suppresses all timeout actions whenever any non-timeout protocol action exists anywhere.
  • After GST models the stable regime “after GST with sufficiently large timeouts.” It is stronger than formal DLS partial synchrony: there is no logical clock, explicit GST time, or Δ-bounded delivery.

Notes

  • The pseudocode is taken from the paper The latest gossip on BFT consensus by Ethan Buchman, Jae Kwon, and Zarko Milosevic, 2019.
