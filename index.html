Step-by-step state machine simulator of Tendermint consensus protocol with interactive pseudocode

Features

  • Display per-node states and messages in a timeline.
  • Trigger enabled steps on nodes with a click. Undo last step.
  • Interactive pseudocode panel: enabled steps are highlighted in the code and can be fired by clicking them.
  • Late or lost messages: Click a sender in the inbox to mark the message as not received. Click again in the same state to revert, or in a later state to show it arrived late.
  • Predefined traces: replay saved scenarios or save the current one as JSON.

Assumptions

  • 4 nodes (n = 3f+1, f = 1). Single height. Values always valid. Non-Byzantine.
  • Implementation agnostic: only follows the Tendermint paper.
  • Instant delivery: every broadcast reaches every inbox immediately. "Late" is a visualization, not a network model.
  • The inbox of a node state lists messages that a node can receive at that state, not necessarily those that have been processed. Messages could be in-flight or even never sent. A message that has been "used" by a step cannot be marked as not received.
  • Starting a timer is modeled as a state transition. That is, timers don't start automatically when conditions are met; one has to trigger a step. Similarly for timeouts: they fire with some steps (state transitions). One could consider timers as part of the state.

Notes

  • The pseudocode is taken from the paper The latest gossip on BFT consensus by Ethan Buchman, Jae Kwon, and Zarko Milosevic, 2019.
